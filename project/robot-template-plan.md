# Robot website templates and interactive demos

## Requested outcome

Add Justin Yu's personal site and eight related project pages as separate collection entries: WARP-RM, EgoMI, Real2Render2Real, POGS, LEGS, CaP-X, SARM and SARM2. Archive available website source and assets locally with pinned provenance, technology, entry points, run instructions, licensing and dependencies. Build reusable robot interaction demos from mature Viser and Three.js components, and verify actual rendering and controls.

## Implementation

1. Acquire eight website repositories and identify frontend code separately from research pipelines. Preserve original archives, including referenced static recordings and viewer builds where available.
2. Record each source in `catalog/justin-sources.json` and `docs/reuse/justin-sources.md`. Keep machine-specific archive paths in a local inventory, outside the published repository.
3. Add nine collection entries with original page previews. Publish licensed, lightweight website snapshots where practical; use original-site embeds for pages without explicit redistribution permission, with a direct original-site fallback. Track which assets need the original host.
4. Add three independent demos: a Three.js robot hero, a Three.js joint/trajectory player, and a self-hosted Viser static replay generated by a reproducible Python script. Keep shared viewer and camera modules reusable.
5. Preserve the existing card visual design, tags, concise text and English/Chinese switching. Record source details in the reuse catalog, outside the collection homepage.
6. Validate desktop/mobile rendering, camera controls, play/pause/scrubbing, reduced motion, direct nested URLs and asset loading. Build, test, publish and verify the deployed routes.

## Completion evidence

- Source inventory records commit IDs and license evidence, including any unavailable or external assets.
- Three interactive demos run with local assets and support static deployment.
- Website collection entries provide a working page view or clearly identified original-site entry.
- Reuse documentation names exact core files and commands rather than requiring another source search.
