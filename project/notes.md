# 机器人主体动画：构建方法与复用说明

记录日期：2026-10-09。

用户已确认：将机器人／机械臂主体的 ASCII、粒子及拖尾动画，作为后续自有项目网站的主要功能之一。已有三维实现可以复用；视频驱动流程列为下一阶段核心功能，尚未实现。

## 1. 已完成的构建方法：实时三维 → 字符／粒子

当前演示：https://shuaijun-liu.github.io/pages/examples/fieldwork/

首版历史基线：`5bd441a`；成功部署触发提交：`67c85f1`。该版本完成了生产构建、8 项浏览器测试，以及正式网址的动画、暂停恢复、主题、场景切换、手机布局检查。

```text
原创基础几何／机器人模型
  → 关节层级与时间驱动姿态
  → 相机与灯光
  → 低分辨率离屏 WebGL 渲染
  → 读取像素颜色、亮度、透明度
  → 亮度映射为字符密度或点大小
  → 全尺寸 Canvas 合成主体、运动拖尾
  → 接入网站布局、主题和控制按钮
```

当前版本已扩展为采摘、双夹爪持杯、折衣和奔跑四场景，并加入约 8 秒轮播与字符消散过渡。人形使用 BSD 授权 G1 模型。

源码定位：

| 模块 | 当前位置 | 复用内容 |
| --- | --- | --- |
| 模型、关节、灯光 | `src/scenes.js` / `RobotRig`、`makeArm()` | 人形关节层级、独立双臂与道具 |
| 运动定义 | `src/scenes.js` / 各场景 `update()` | 四类动作时间函数；未来可替换为模型动画或关节轨迹 |
| 字符／粒子表现 | `src/motion.js` / `draw3D()` | 离屏采样、透明像素过滤、亮度映射、强调色 |
| 轨迹 | `src/motion.js` / `drawTrails()` | 多关节世界坐标历史、按当前相机投影、渐隐拖尾 |
| 主题、控制、曲线、文案 | `src/main.js` | 暂停、恢复、场景切换、明暗主题、逐字文字 |
| 响应式页面 | `src/style.css`、`examples/fieldwork/index.html` | 首屏主场景、移动端布局、键盘操作与内容组织 |
| 发布与验证 | `.github/workflows/deploy.yml`、`tests/site.spec.js` | 静态构建、行为测试、GitHub Pages 发布 |

当前实现参数：约 30 帧/秒的渲染上限、设备像素比上限 2；字符采样单元按画面宽度取 8 或 13 CSS 像素；每条关节轨迹最多保留 58 个点。具体值以源码为准。它们是现有演示参数，不是未来所有视频的固定标准。

现有四条曲线为归一化关节角度、数值角速度、数值角加速度与场景运动信号，属于模拟量。页面隐藏或动画暂停时停止循环；低动态偏好默认静止；无 WebGL 或上下文丢失时使用二维备用渲染。

## 2. 下一阶段核心路线：机器人视频 → 主体动画

默认优先采用这条路线来使用用户自己的真实机器人动作。目标是保留原视频动作，以字符／粒子形式融入项目首屏，而不是要求先完成三维重建。

```text
用户视频
  → 选择动作片段与画面范围
  → 提取机器人主体遮罩，并保持跨帧稳定
  → 裁剪、缩放、主体定位、循环衔接
  → 准备网站播放素材与可选二维运动轨迹
  → 视频帧 + 遮罩 → 低分辨率颜色／亮度采样
  → ASCII／粒子主体 + 渐隐拖尾
  → 接入已有网站的主题、播放控制与响应式布局
```

### A. 素材检查

记录视频来源、可用权限、分辨率、帧率、时长、镜头运动、遮挡、动作周期，以及希望保留的主体范围。主体可包含机械臂、全身机器人，或完成任务时需要一起展示的夹持物。

先选一小段清晰动作验证效果，再扩展到完整展示片段。首轮交付包含原片段、主体分离预览和字符动画预览，便于直接对照。

### B. 主体提取与稳定

背景简单时可用背景差分、色彩分离或人工辅助遮罩；复杂背景需要视频主体分割与跨帧传播。具体方法在收到素材后选择。

重点检查细夹爪、连杆、镂空处与遮挡边界；通过时序平滑减少遮罩闪烁。移动镜头可在主体定位阶段做稳定处理，以保持首屏构图。

### C. 播放素材准备

采用发布前离线处理、网站静态播放的结构。优先准备 RGB 与主体遮罩的对应帧；也可使用经目标浏览器验证的带透明度素材。RGB 与遮罩必须共享尺寸、帧索引、裁剪变换和时间戳。

同时产出首帧海报与轻量备用视频。以实际手机和桌面浏览器验证解码、加载、循环衔接与画质，再确定分辨率和压缩参数。大型原始素材保留在网站源码仓库之外；发布目录只放需要的优化产物。

### D. 字符与粒子映射

遮罩决定哪些像素属于主体，避免背景也变成满屏字符。主体亮度决定字符或粒子的密度，配色可以统一为网站品牌色，也可保留少量原视频强调色。

对亮度、遮罩与字符阈值做时间上的稳定处理，降低字符跳闪。按实际解码帧更新，暂停、切换片段、循环跳转时同步清理或重置相关状态。

### E. 运动拖尾

视频路线采用屏幕空间轨迹：可跟踪夹爪／末端的二维位置，或叠加按时间衰减的主体历史遮罩。跟踪质量不足时先使用历史轮廓拖尾，不必让三维姿态估计成为视觉样例的前置条件。

现有三维路线继续使用世界坐标轨迹。两种轨迹的含义分别保留，不将视频二维轨迹标记为三维运动测量。没有真实关节数据时，展示播放进度或明确命名的二维运动指标即可。

### F. 网站接入

优先复用已有主场景容器、主题、播放按钮、ASCII／POINTS 切换、低动态模式和手机布局。需要提供海报、加载、播放失败及静态备用状态；自动播放不可用时显示可操作的播放入口。

此阶段目标是把准备好的用户视频变成项目展示内容。访客上传、在线分割服务和后台管理不属于已确认范围。

## 3. 何时采用三维路线

| 输入条件 | 优先路线 | 视角能力 |
| --- | --- | --- |
| 单段机器人视频 | 视频主体分离 → 字符／粒子 | 保留视频视角；可平面缩放和拖动，不能凭空查看背面 |
| 已有三维模型与动画／关节轨迹 | 模型动画 → 复用当前三维渲染 | 可自由旋转相机、缩放并调整动作 |
| 只有视频，但明确要求自由视角 | 另设模型获取、运动恢复或三维重建阶段 | 按可获得的模型与多视角信息验证 |

“主体动画”视觉效果不等于三维重建。默认先实现能保留真实动作的视频路线；自由视角作为有相应素材时的增强能力。

## 4. 后续复用的组件边界

建议把内容来源与视觉表现分开：

- **内容来源**：程序化三维、已有模型动画、预处理视频。
- **视觉表现**：字符集、采样密度、粒子大小、主题色、背景透明度、拖尾长度。
- **播放状态**：播放／暂停、片段切换、速度、循环、低动态模式。
- **相机或构图**：三维来源提供轨道相机；视频来源提供二维构图控制。

先复用现有源码，完成一段用户视频后再提取通用组件；不提前重构整个网站框架。

## 5. 下一阶段验收

1. 使用至少一段用户提供的机器人／机械臂视频，主体动作与原片段一致。
2. 背景正确分离，夹爪和细杆结构可辨，边缘与字符没有明显闪烁。
3. ASCII、粒子与拖尾效果能作为首页主视觉播放，文案不遮挡主要动作。
4. 暂停恢复、循环、切换片段、主题切换和低动态模式行为正确。
5. 在桌面和手机上验证实际加载时间、帧率与画面完整性，并据测量调整参数。
6. 发布素材与网站一起部署，使用子路径仍能正确加载；仓库保存处理参数和复现说明。
